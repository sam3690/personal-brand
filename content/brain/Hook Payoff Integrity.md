# Hook Payoff Integrity

The one law behind every post that works: **the payoff must match the SHAPE the hook promised.**
Justin Welsh's whole method reduces to this: "the body delivers exactly what the trailer promised."

## The failure that named this note
The 2026-07-06 "5 boring automations" carousel promised a **list of 5** and rendered as **one connected
pipeline** in 5 steps. List hook, process payoff. The reader felt baited, even though every fact was true.
[[The Seven Bones]] can be perfect and the post still fails if the shape breaks.

## Match the shape
- A count ("5 X", "7 X") promises that many DISTINCT, standalone items. Not one thing in N steps.
- "How I built X" promises the ordered steps of that ONE build. Not a grab-bag of tips.
- Each counted item in a carousel = its own slide the reader could screenshot alone.

## The test (do this before every publish)
Cover the hook. Read only the body/slides. Ask: "what did this promise?" If the answer isn't the hook,
one of them is wrong. Enforced as a hard gate by Agent 5 QA (`content/agents/5-algorithm-qa.md`).
